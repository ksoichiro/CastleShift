# MC 26系（26.1.2 / 26.2）対応 実装計画

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** CastleShift を Minecraft 26.1.2 / 26.2（Fabric・NeoForge・Forge）でビルド可能にする。

**Architecture:** 既存のマルチバージョン構成（`props/{ver}.properties` + `common/{ver}` + `{loader}/{ver}` ディレクトリ複製）を踏襲。`common/1.21.11` 系を雛形に複製し、MC26 の API 差分とツールチェーン（Java25 / Loom / ForgeGradle / Gradle）を解消する。リスクの高いツールチェーン問題を「26.2 × Fabric」の最小縦切りで先に潰し、確立した手順を他ローダー・26.1.2 へ展開する。

**Tech Stack:** Gradle（Architectury Loom / ForgeGradle）、Architectury API、Mojang official mappings、Java 25。

## Global Constraints

- 対象バージョン: `26.1.2`、`26.2`（各系統の最新パッチ）。`target_mc_version` 文字列・ディレクトリ名にこの値を用いる。
- Java: 両バージョンとも **Java 25**（props の `java_version=25`）。
- ローダー: `fabric,neoforge,forge`（全3種）。
- 既存バージョン（`1.20.1`, `1.21.1`〜`1.21.11`）を壊さない。ルート共通ファイル（`build.gradle` / `gradle.properties` / `settings.gradle` / `gradle/wrapper`）を変更したら必ず既存版の非回帰を確認する。
- `run/`・`.gradle/`・ビルド生成物はコミットしない（`.gitignore` 準拠）。
- コミットはユーザー指示があるまで行わない（本リポジトリ運用ルール）。各タスクの「Commit」ステップはユーザー承認後に実行する。
- 依存バージョン（確定値）:
  - fabric_loader: `0.19.3`
  - fabric_api: 26.1.2 → `0.153.0+26.1.2` / 26.2 → `0.153.0+26.2`
  - neoforge: 26.1.2 → `26.1.2.76` / 26.2 → `26.2.0.7-beta`
  - forge: 26.1.2 → `64.0.10`（major 64）/ 26.2 → `65.0.1`（major 65）

**Files:**

- Create: `fabric/26.2/build.gradle`（`fabric/1.21.11/build.gradle` を複製・改変）

- Produces: `common/26.2`（`:common-26.2` プロジェクト）。Fabric/NeoForge/Forge の build.gradle が `commonModule` として参照。

- [ ] **Step 1: common/26.2 ソースを 1.21.11 から複製**

- [ ] **Step 6: supportedVersions に 26.2 を追加**


- [ ] **Step 7: 初回ビルドを実行してツールチェーン問題を洗い出す**

Run: `./gradlew :fabric:build -Ptarget_mc_version=26.2 --stacktrace`
Expected（最初は失敗しうる）: 以下のいずれかのカテゴリのエラーを確認する。
1. Gradle が Java25 toolchain / `release=25` を扱えない（例: `Could not target platform: 'Java SE 25'`、unknown toolchain）。
2. foojay-resolver が JDK25 を解決できない。
3. Architectury Loom / architectury-plugin が MC `26.2` を解決できない（mappings/`minecraft` 取得失敗）。
4. ソースの API コンパイルエラー（Mojang mapping 差分）。

- [ ] **Step 8: ツールチェーン系エラー（1〜3）を解消**

エラーカテゴリに応じて、影響範囲の小さい順に対処する。**ルート共通ファイルの変更は既存版に影響するため、変更したら Task 4 で非回帰確認する。**

- カテゴリ2（foojay）: `settings.gradle:13` の `org.gradle.toolchains.foojay-resolver-convention` を最新版へ。最新版番号は Gradle Plugin Portal で確認:
  Run: `curl -s "https://plugins.gradle.org/m2/org/gradle/toolchains/foojay-resolver-convention/maven-metadata.xml" -o "$TMPDIR/foojay.xml"; grep -oE '<latest>[^<]*</latest>' "$TMPDIR/foojay.xml"`
- カテゴリ1（Gradle 本体の Java25 非対応）: `gradle/wrapper/gradle-wrapper.properties` の `gradle-8.14-bin.zip` を Java25 対応版（Gradle 9 系）へ更新。対応版は Gradle 互換性表（https://docs.gradle.org/current/userguide/compatibility.html）で確認。**注意**: Gradle 9 系へ上げると ForgeGradle / Loom が動かなくなる恐れがあるため、まず loom/architectury/ForgeGradle が要求する Gradle 版を確認し、すべてを満たす版を選ぶ。満たせない場合は「JDK25 toolchain を別途インストールし、Gradle 自体は現行のまま toolchain だけ 25 を使う」構成が可能か検証する。
- カテゴリ3（Loom が MC26 非対応）: `build.gradle:2-3` の `dev.architectury.loom`（現 `1.13-SNAPSHOT`）/ `architectury-plugin`（現 `3.4-SNAPSHOT`）を MC26 対応版へ。対応版は Architectury のドキュメント/Maven（https://maven.architectury.dev/）で確認。

各変更後に Step 7 のビルドを再実行し、エラーカテゴリが解消したことを確認する。

- [ ] **Step 9: ソース API コンパイルエラー（カテゴリ4）を解消**

`./gradlew :common-26.2:compileJava -Ptarget_mc_version=26.2 --stacktrace` でコンパイルエラーを列挙し、`common/26.2/src/main/java/com/castleshift/` の対象ファイル（`CastleShift.java`, `mixin/StructureStartMixin.java`, `world/processor/*`）を MC26 の API/マッピングに合わせて修正する。修正は「メソッド/クラスのリネーム追従」「シグネチャ変更追従」に限定し、ロジックは変えない。エラーが消えるまで反復する。

Run: `./gradlew :common-26.2:compileJava -Ptarget_mc_version=26.2`
Expected: BUILD SUCCESSFUL

- [ ] **Step 10: Fabric ビルド成功を確認**

Run: `./gradlew :fabric:build -Ptarget_mc_version=26.2`
Expected: BUILD SUCCESSFUL（`fabric/build/libs/castleshift-0.2.0+26.2-fabric.jar` 等が生成）

- [ ] **Step 11: pack_format を確定**

26.2 クライアント jar 内の `version.json`（`pack_version.resource` / `.data`）で正しい pack_format を確認し、`props/26.2.properties` の `pack_format` を実値へ更新する。確認方法:
Run: `curl -s "https://piston-meta.mojang.com/mc/game/version_manifest_v2.json" -o "$TMPDIR/mm.json"; grep -oE '"url": "[^"]*/26\.2\.json"' "$TMPDIR/mm.json"`
→ 得た URL の json 内 `downloads.client.url` の jar を取得し、jar 内 `version.json` の `pack_version` を読む（または minecraft.wiki の Pack format 表で 26.2 の値を確認）。
更新後、再度 `./gradlew :fabric:build -Ptarget_mc_version=26.2` が成功することを確認する。
